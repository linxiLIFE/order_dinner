# 自动发布

Push 到 `main` 或 `codex/ai` 会触发 `.github/workflows/deploy.yml`。部署串行执行，不取消正在运行的发布。

流程：读取线上版本 → 自动递增版本 → PostgreSQL 隔离集成测试、安卓和 Windows 并行构建 → 合并安装包与更新清单 → 服务器构建候选镜像 → 数据库备份 → 更新应用 → 校验线上网页、APK、EXE 的 SHA-256 → 清理旧版本。

CI 版本取源码和线上版本中较高者，再递增一位；仅修改构建工作目录，不回写 Git。数据库备份与部署共用服务器文件锁。候选版本不高于线上版本时拒绝部署。

服务器先将旧安装包复制到候选目录，再通过 rsync 仅上传有变化的数据块，避免每次跨境传输完整 Windows 安装包。运行中的安装包不修改、不使用硬链接；传输完成后仍校验完整文件的 SHA-256。

GitHub 仓库 Secrets：

- `DEPLOY_SSH_KEY`：服务器 SSH 私钥。
- `DEPLOY_KNOWN_HOSTS`：已核实的服务器 SSH 主机公钥记录；强制验证主机身份。
- `ANDROID_KEYSTORE_BASE64`：当前已安装安卓客户端使用的 debug.keystore 的 Base64；沿用已有测试签名，不生成新密钥。若改用正式签名，需同步调整打包配置并处理旧签名客户端迁移。

Windows 安装包目前没有代码签名证书。服务器 `.env` 保持原样，生产密钥不上传到构建作业。服务端采用 CI 测试通过的预编译文件。

按用户要求不自动恢复应用。健康或文件校验失败则作业失败，保留部署目录供排查。新数据库备份生成并通过 gzip 校验后，旧备份移入服务器废纸篓；全部线上验证通过后，旧应用目录及其中的安装包移入废纸篓，活动目录只保留当前版本。废纸篓不会自动清空，仍占磁盘空间。

每日 03:00 按服务器时区备份。备份目录仅保留最新一份；每天的新备份也会替代部署前的那一份，不代表长期保留每个部署的数据库快照。

本地未提交修改不会进入 CI；CI 始终构建 Push 对应的 Git 提交。真实设备升级和打印验收需另行验证。
